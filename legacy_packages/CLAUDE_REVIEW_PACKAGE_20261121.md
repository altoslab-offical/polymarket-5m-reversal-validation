# 規劃者審查：`polymarket-5m-strategy_2026-11-21`（BTC / ETH / SOL 三資料夾）

## 結論：不要換成這套。它就是 4.2 裡的 `v1` 前身，而且是修 bug 之前的版本。
- 參數和 4.2 預註冊的 `v1` 幾乎完全一樣：
  - 進場時段 150–255 秒、z ≥ 1.30、p ≥ 0.80、價格帶 [0.68, 0.82]、EV ≥ 3.5¢
  - Student-t df 4.5、波動率回看 180 秒、Oracle gap 6 bps、停損 z −0.35
- `v1` 已經在 11/21 開始的主判定裡用修正後的程式測試。換成這套，等於拿掉已經修好的版本，改用還沒修好的版本。

## 這套程式仍存在、而且已在 4.2 版本修掉的問題
| 問題 | 這套程式 | 4.2 版本 |
|---|---|---|
| 結算模型 | `pricing_model` 只用 Chainlink **現價**算 z。結算其實看的是最後 60 秒 **TWAP**，最後 60 秒的機率會估錯 | `v2` 系列使用 TWAP 投影 |
| 波動率來源 | Binance 和 Coinbase 混合，180 秒 | 統一用 Binance 1 秒收盤，1,800 秒暖機 |
| 重啟暖機 | 沒有 | 未滿 1,800 秒不交易 |
| 盤口新鮮度 | 只檢查 Chainlink 年齡（4.5 秒） | 毫秒級 `book_age` / `book_lag` 檢查，舊資料決策 = 0 |
| 模擬成交 | 不是 4.2 的 +1 秒逐檔深度 FAK 模型 | 已驗證逐檔深度、+1 秒成交 |
| 手續費 | 寫死 0.07 | 11/20 之後：BTC 0.05、ETH/SOL 0.01 |

## 績效數字不能當證據
- `config.py` 註解寫的「77 筆、勝率 90.9%」「n = 59、勝率 94.9%」「64 筆、勝率 90.6%」，都是**用同一批重播資料調參數之後的樣本內結果**，有過擬合。
- `backtest.py --demo` 用的是**亂數產生的假行情**，不是真實資料。
- 同一套邏輯修 bug 前的 runner，在 11/18 的紙上模擬前 4 單輸 3 單。鑑識結果：輸單原因是過期盤口和起始價抓錯。

## 真錢風險
- 內含 `--live` 實盤下單功能，預設每單 25 U，每日虧損熔斷 25 U。以 40 U 本金來說，**一天就可能虧掉六成**。
- 4.2 通過之前，**不要用 `--live` 執行**。

## 可以參考的部分（不改動 4.2）
- `probe_ptb.py`、Gamma `priceToBeat` 校正、Polygon 鏈上 Chainlink 備援：這些是工具，沒有策略內容。如果 4.2 通過、準備實盤，可以評估是否沿用。
- `live_executor.py` 的 HTTP/2 連線預熱（約 150 ms 下單）：實盤階段值得參考。實盤前要先用 5 股試跑，驗證下單延遲。
