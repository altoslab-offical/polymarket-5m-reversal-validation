## 一、觸發紀律第 5 條回報：`Live Shadow Parity = 0 / 4`（`0.0% < 99%`）

截至 `2026-11-19 16:04 +08:00`（`08:04 UTC`），於 `window_ts >= 1795059300` 共累積 **`147` 個重疊幣窗**，但 `Recorder (v2_filtered)` 記錄 `2` 筆 `ENTER`、`PAPER_40U Runner` 記錄 `4` 筆 `ENTER`，兩者匹配 **`0 / 4`（`0.0%`）**，明確低於 `99%` 門檻。

### 1. 實證基礎設施 Bug：Recorder CLOB WebSocket 頻繁 `1013 slow consumer`（延遲達 `2.2–2.5s`）
- **`snapshots_1hz` 延遲分佈**（`window_ts >= 1795059300`，`n = 46,860` 秒）：

- **Log 實證**（`data/validation_42/recorder_42.log`）：自 `11:32` 重啟後數小時內持續出現數十次：
  `CLOB WS reconnect: received 1013 (try again later) slow consumer: send buffer full`
- **根因**：`live_recorder_42.py` 的 `websockets.connect(..., max_queue=64)` 與每秒同步 SQLite `INSERT / COMMIT` 及結算查詢共用同一條 `asyncio` event loop；對照同機器使用 `aiohttp` 且無同步 SQLite 阻塞的 `PAPER_40U Runner`，同期 CLOB 延遲僅 `4 ~ 154 ms`、零 `1013` 斷線。
